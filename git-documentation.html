Git Version Control - Step by Step Guide

Step 1: Create a GitHub Repository

Log in to GitHub, click New Repository, enter a repository name, choose Public or Private, and click Create Repository.

Step 2: Create a Local Folder

Create a folder where you want to store your projects.


mkdir github-projects
cd github-projects
ls

Step 3: Clone the Repository

Copy the repository URL from GitHub and run:


git clone https://github.com/your-username/your-repo-name.git
touch filename.html

Step 4: Open the Repository

Navigate into the cloned repository folder.


cd your-repo-name

Step 5: Add Project Files

Create or copy your files into the repository folder.

Step 6: Save Changes with Git

Stage and commit your changes:


git add .

or stage a specific file:


git add filename.html

Then commit with a message:


git commit -m "Initial commit"

Step 7: Upload to GitHub

git push origin main

Refresh your GitHub repository page to verify that your files have been uploaded successfully.

Git Pull

git pull updates your local repository with the latest changes from GitHub.

  • Make sure to commit your changes before pulling to avoid conflicts.
  • Mainly used when working with collaborators or multiple devices.
  • If you work alone, you may not need to use git pull often.

Git Log

git log displays the commit history of your repository.

Git Reset

git reset is used to undo commits or changes in your repository.

Reset Commands

git reset --soft HEAD~1
Undoes the last commit but keeps changes staged.
git reset --hard HEAD~1
Undoes the last commit and deletes all changes.
git reset --hard origin/main
Resets your local branch to match GitHub and removes all local changes.
git reset --hard <commit-hash>
Moves your project back to a specific commit and removes later changes.
git reset --soft <commit-hash>
Moves your project back to a specific commit but keeps changes staged. The commit hash can be found in the output of git log.
git reset --hard ORIG_HEAD
Undoes the last reset command and restores the previous state of the repository. Helpful if you accidentally reset to the wrong commit or want to revert a reset action.

Git Restore

git restore filename.html
Restores a specific file to its state in the last commit. Useful if you want to discard changes made to a file and revert it back to the version in the last commit.
git restore --staged filename.html
Unstages a file that has been added to the staging area. Useful if you accidentally staged a file and want to remove it from the staging area without discarding the changes.
git restore .
Restores all files in the current directory to their state in the last commit. Useful if you want to discard changes made to multiple files and revert them back to the version in the last commit.

Git Status & Inspection

git status
Displays which files have been modified, staged, or are untracked. Essential for seeing what changed before committing.
git diff
Shows the specific changes you made to files (what was added/removed/modified).
git diff --staged
Shows what changes are staged and ready to be committed.
git show <commit-hash>
Shows the complete details of a specific commit including what changed.

Git Branching

Branches let you create separate versions of your project to work on features without affecting the main code.

git branch
Lists all branches in your local repository. Current branch is marked with *.
git branch branch-name
Creates a new branch (but doesn't switch to it).
git checkout branch-name
Switches to a different branch. Your working files will update to that branch's state.
git switch branch-name
Newer alternative to checkout for switching branches (same functionality).
git checkout -b new-branch-name
Creates a new branch AND switches to it immediately (combines two commands).
git switch -c new-branch-name
Newer way to create and switch to a new branch (alternative to checkout -b).
git branch -d branch-name
Deletes a branch. Use -D to force delete even if changes aren't merged.
git branch -m old-name new-name
Renames a branch from old-name to new-name.

Git Merge & Rebase

git merge branch-name
Merges another branch into your current branch. Creates a merge commit showing the combine.
git rebase branch-name
Alternative to merge - replays your commits on top of another branch. Creates a cleaner history but is riskier.
git rebase -i HEAD~n
Interactive rebase - lets you edit, combine, or reorder your last n commits.

Git Stash

Temporarily save changes without committing, useful when you need to switch branches.

git stash
Saves your uncommitted changes temporarily so you can work on something else.
git stash save "message"
Saves changes with a descriptive message so you remember what was stashed.
git stash list
Lists all your stashed changes.
git stash pop
Restores the most recent stash and removes it from the list.
git stash apply stash@{n}
Restores a specific stash but keeps it saved (doesn't remove it).
git stash drop stash@{n}
Deletes a specific stash if you don't need it.
git stash clear
Deletes all stashes (careful - this can't be undone!).

Git Remote Operations

git remote
Lists all remote repositories (usually "origin" for GitHub).
git remote -v
Shows remote names and their URLs (where they point to).
git remote add origin <url>
Connects your local repository to a GitHub URL.
git fetch
Downloads changes from GitHub without merging them (safer than pull).
git fetch origin branch-name
Downloads a specific branch from GitHub.
git pull origin branch-name
Downloads and merges changes from GitHub in one command.
git push origin branch-name
Uploads your branch to GitHub.
git push -u origin branch-name
Uploads branch and sets it to track GitHub version (easier future pushes).
git push --all
Pushes all branches to GitHub.
git push --force
Forces push even if it overwrites remote changes (dangerous - use carefully!).

Git Revert & Undo

git revert <commit-hash>
Creates a new commit that undoes a previous commit (safe, keeps history visible).
git checkout <commit-hash> -- filename
Restores a specific file from a previous commit.
git clean -fd
Deletes all untracked files and folders (files Git doesn't know about).

Git Commit Modifications

git commit --amend
Modifies the last commit (change message or add files to it).
git commit --amend --no-edit
Adds changes to the last commit without changing the message.
git cherry-pick <commit-hash>
Applies a specific commit from another branch to your current branch.

Git Configuration

git config --global user.name "Your Name"
Sets your name for all commits (--global applies to all your projects).
git config --global user.email "your@email.com"
Sets your email for all commits.
git config --list
Shows all your current Git configuration settings.
git init
Initializes a new Git repository in the current folder.

Git Tags & Versions

git tag
Lists all tags (version markers) in your repository.
git tag -a v1.0 -m "Version 1.0"
Creates a tag (version marker) for an important commit.
git push origin v1.0
Uploads a tag to GitHub.
git push origin --tags
Uploads all tags to GitHub.

Git Inspection & History

git blame filename
Shows who changed each line in a file and when (great for tracking down bugs).
git log --oneline
Shows commit history in a short, readable format (one line per commit).
git log --graph --all --decorate
Shows commit history as a visual graph showing all branches.
git log -p
Shows commit history with the actual changes in each commit.
git log --author="name"
Shows only commits made by a specific author.
git reflog
Shows reference logs of all changes (useful for recovering lost commits).
git whatchanged
Shows what files changed in each commit with more detail than git log.

Git Add & Commit (Advanced)

git commit -am "message"
Stages all tracked files AND commits in one command (doesn't add new untracked files).
git add -u
Stages only modified/deleted tracked files (doesn't add new files).
git add -A
Stages all changes including new files, modifications, and deletions.
git add .
Stages files in current folder and subdirectories (different from -A for deletions).
git commit -m "message" --no-verify
Commits without running pre-commit hooks or checks.
git commit --allow-empty -m "message"
Creates a commit with no actual changes (useful for triggering builds).
git add -p
Interactive staging - choose which changes to stage (part of a file).

Git Status & Inspection (Advanced)

git status -s
Shows status in compact format (short form).
git status --porcelain
Shows status in a format optimized for automation.
git diff HEAD
Shows all changes (staged and unstaged) since the last commit.
git diff --cached
Shows only staged changes (alternative to --staged).
git diff branch1 branch2
Compares differences between two branches.
git fsck
Checks if the repository is healthy and intact.

Important Note

⚠️ Resetting means changes are removed from your local repository, but they are not gone from GitHub. You can always pull the changes from GitHub to restore the files in your local repository if you have reset them by mistake.
